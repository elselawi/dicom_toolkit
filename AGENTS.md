# AGENTS.md — dicom_toolkit

## Project Identity

**dicom_toolkit** is a Flutter plugin for workstation-grade DICOM medical imaging. It pairs a **Rust native core** (`dicom` crate v0.9) with **GPU fragment shaders** (GLSL) to deliver 16-bit precision, real-time windowing (contrast/brightness), and zero-UI-thread-blocking rendering. The Dart↔Rust bridge is powered by `flutter_rust_bridge` v2.12.0.

- **License**: GPL v3 (with CLA for commercial dual-licensing)
- **Platforms**: Android, iOS, Linux, macOS, Windows (all FFI)
- **Current version**: `0.1.0+3`

## Architecture (Two-Sided)

```
Flutter (Dart)                          Rust (native)
─────────────────                      ─────────────────
DicomViewer widget
  └─ DicomShaderPainter (CustomPaint)
       └─ GLSL frag shader ─────────────────────────┐
DicomController (ChangeNotifier)                     │
  └─ DicomService (DI-able loader)                   │
       └─ RustDicomLoader                            │
            └─ loadDicom() ──FFI──→ process_dicom_file()
                                      ├─ dicom::object::open_file
                                      ├─ extract 27 DICOM tags
                                      └─ extract pixel data → Vec<i16>
```

### Data Flow

1. `RustLib.init()` loads the native `.so`/`.dylib`/`.dll`
2. `DicomController.initialize()` compiles `dicom_window.frag`
3. `loadFromBytes()` → service → loader → Rust FFI → parses `.dcm`
4. Rust returns `DicomFrameResult` (metadata + `Vec<i16>` pixels)
5. Dart packs 16-bit → RGBA: R=high byte, G=low byte, +32768 offset
6. `DicomShaderPainter` passes uniforms + texture to GPU shader
7. Shader unpacks 16-bit, applies Hounsfield transform + windowing

## Coding Conventions

### Dart

- **Imports**: relative imports (`../core/...`), NOT package imports (except the public `dicom_toolkit.dart` barrel)
- **Lint**: `package:lints/recommended.yaml` + strict rules in `analysis_options.yaml`
- **Generated code**: `lib/src/rust/**` is excluded from analysis — NEVER hand-edit it
- **Naming**: camelCase for variables/methods, PascalCase for classes, snake_case for files
- **Const constructors**: prefer `const` everywhere possible
- **`final` over `var`**: always use `final` for locals and fields that don't reassign
- **`void` callbacks in tear-offs**: use `() => controller.clear()` not `controller.clear`
- **Dispose**: always call `dispose()` on `DicomController` in `State.dispose()`

### Rust

- **Edition**: 2021
- **Error handling**: `anyhow::Result` for all public-facing functions
- **DICOM tag access**: Use the helper functions (`get_str_tag`, `get_float_tag`, `get_int_tag`) defined in `process_dicom_file.rs` for clean, consistent extraction with automatic fallback handling.
- **Pixel extraction**: 4-tier approach: 8-bit raw bytes (respects signedness) → 16-bit direct byte-chunking (`i16::from_le_bytes`) → `to_multi_float64` (transfer-syntax-aware) → `to_multi_int::<i16>` (last resort)
- **Struct conventions**: derive `Debug, Clone` on models; use `#[frb(sync)]` for sync-only structs
- **Release profile**: `opt-level=3`, `lto="thin"`, `codegen-units=1`, `panic="abort"`, `strip="symbols"`

## Key Patterns

### 16-bit Precision Through 8-bit Textures

Flutter's `ui.Image` only supports 8-bit RGBA. We pack each 16-bit pixel into R (high byte) and G (low byte):
```dart
final val = data[i] + 32768;          // offset to unsigned u16
rgbaData[i * 4 + 0] = (val >> 8) & 0xFF;  // R = high byte
rgbaData[i * 4 + 1] = val & 0xFF;         // G = low byte
```
The GLSL shader reverses this:
```glsl
float high = texColor.r * 255.0;
float low = texColor.g * 255.0;
float raw_value = (high * 256.0 + low) - 32768.0;
```

### Dependency Injection for Loaders

```dart
// Default: local files
final controller = DicomController();

// Custom: inject a network/PACS loader
final service = DicomService(loader: NetworkDicomLoader());
final controller = DicomController(service: service);
```
Implement `IDicomLoader` for new backends.

### Tag Extraction Helpers

All DICOM tag extraction in `process_dicom_file.rs` uses three generic helpers instead of inline `.map().unwrap_or()` chains:

```rust
fn get_str_tag(obj: &DefaultDicomObject, tag: Tag) -> Option<String>  // trims whitespace
fn get_float_tag(obj: &DefaultDicomObject, tag: Tag, default: f32) -> f32
fn get_int_tag<T: TryFrom<i64> + Copy>(obj: &DefaultDicomObject, tag: Tag, default: T) -> T
```

When adding a new tag, use the appropriate helper — it handles missing elements, type conversion errors, and default fallbacks automatically.

### Shader Uniform Binding Order

In `DicomShaderPainter.paint()`, uniforms are bound by index — keep this order:
| Index | Uniform |
|-------|---------|
| 0 | `u_resolution` (vec2: width, height) |
| 1 | (height) |
| 2 | `u_window_center` |
| 3 | `u_window_width` |
| 4 | `u_rescale_intercept` |
| 5 | `u_rescale_slope` |
| sampler 0 | `u_texture` (the RGBA-packed image) |

## Common Pitfalls

1. **Editing generated code**: Files under `lib/src/rust/` and `rust/src/frb_generated.rs` are auto-generated. Changes will be overwritten. Edit only the hand-written Rust in `rust/src/api/`.

2. **Shader asset path**: Must use `packages/dicom_toolkit/assets/shaders/dicom_window.frag` (not a relative path). The `LibShaders.dicomWindow` constant centralizes this.

3. **Missing DICOM tags**: Not all DICOM files have every tag. The Rust parser handles this via `DicomMetadata::default()`, and the helper functions (`get_str_tag`, `get_float_tag`, `get_int_tag`) automatically fall back to defaults. When adding a new tag, always use the appropriate helper — it handles missing elements, type conversion errors, and default fallbacks automatically.

4. **Controller lifecycle**: `DicomController.dispose()` must be called to free GPU textures. Leaking controllers leaks GPU memory.

5. **`notifyListeners()` after state changes**: Every state mutation in `DicomController` must call `notifyListeners()`. The `DicomViewer` widget uses `ListenableBuilder` which only rebuilds on notification.

6. **16-bit signed assumption**: DICOM pixel data can be signed or unsigned. The +32768 offset in the texture packing handles signed values, but the shader and packing code assume 16-bit signed input.

7. **Release performance**: The `series_performance_test.dart` benchmark expects >60 FPS. Always test performance in release mode (`flutter test --release` or `flutter run --release`).

8. **Cross-platform FFI**: The native library stem is `dicom_toolkit`. Each platform loads from its own path — iOS/macOS from frameworks, Android from JNI libs, Windows/Linux from the executable directory.
